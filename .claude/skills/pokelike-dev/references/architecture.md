## 1. Load order and globals

`index.html` loads nine classic scripts in a fixed order:

```
data/pokedex.js  data/content.js  data/regions.js  data/maps.js
js/core.js  js/map.js  js/battle.js  js/ui.js  js/game.js
```

Top-level `const` in a classic script lands in the shared global lexical scope,
so every file sees every other file's declarations by name. There are no
modules, no imports, no bundler. `data/regions.js` expands its stage tables at
load time and `js/map.js` validates its palettes at load time, which is why data
must come first. `check.mjs` enforces the order.

Objects are also hung off a `Poke` namespace (`Poke.Species`, `Poke.Battle`,
`Poke.Run`, `Poke.Profile`, `Poke.MapGen`…) and a few on `window` for the inline
`onerror` handlers in generated markup. Prefer the bare name inside engine code;
use `Poke.*` from anything that might run before a file has loaded.

Entry point: `js/game.js` ends with
`document.addEventListener('DOMContentLoaded', () => Game.boot())`.

## 2. Data row formats

These are positional arrays, chosen to keep `data/pokedex.js` at 70 KB instead
of 400 KB. A short or misordered row fails silently — it reads `undefined` and
becomes `NaN` three functions later. `check.mjs` validates all of them.

### DEX — 12 columns, index = dexId − 1

```
[0]  name              string
[1]  type1             index into TYPES
[2]  type2             index into TYPES, or -1 for single-typed
[3]  baseHp            [4] baseAtk  [5] baseDef
[6]  baseSpa           [7] baseSpd  [8] baseSpe
[9]  generation        1..9
[10] flags             bitfield: 1 legendary, 2 mythical, 4 baby
[11] captureRate       3..255, the gen-3 catch rate
```

Read through `Species.*` in core.js — `Species.name/types/base/bst/gen/
captureRate/isLegendary/isMythical/isBaby/isSpecial`. `isSpecial` means
legendary **or** mythical (`flags & 3`) and is what holds them out of route
encounter pools.

### MOVES — 6 columns

```
[0] name   [1] type index   [2] power   [3] accuracy (1..100)
[4] category: falsy = physical, truthy = special
[5] priority (0 normally)
```

`MOVES_BY_TYPE[typeIndex]` is a precomputed array of move indices, used by
`Moves.buildFor` to assemble level-appropriate movesets. Every type needs at
least one entry or movesets for it collapse to a fallback.

### EVOLVES — `{ fromDexId: [[toDexId, atLevel], …] }`

Multiple entries mean a branching line (Eevee, Tyrogue); `Battle.checkEvolution`
queues all the ones whose level is met and `Game.resolvePendingEvolutions` asks
the player to choose.

### MEGAS — `{ baseDexId: [[spriteId, label, type1, type2, hp, atk, def, spa, spd, spe], …] }`

`spriteId` is the PokéAPI sprite number for the mega form (10033 etc.), `label`
the display name. Applied in `Battle.doMega`, reverted for the whole team in
`Battle.finish`.

### MAP_IMAGES — `{ stageKey: filename }`

Key is either `stage.id` (`"kanto-5"`) or the readable `stage.imageKey`
(`"kanto|Route 1"`). Prefer the readable form: it survives inserting or
reordering areas, which shifts every numeric id. Values resolve against
`MAP_IMAGE_BASE` (`"maps/"`) or may be absolute URLs. Generated by
`tools/fetch-maps.mjs` — do not hand-edit the manifest block.

## 3. js/core.js

RNG, species access, sprites, audio, persistence, encounter pools.

- **`mulberry(seed)` / `hashStr(str)`** — the deterministic RNG behind maps,
  daily runs and seeded challenges. `todaySeed()` hashes the UTC date.
- **`Species`** — accessors over `DEX` (above). `Species.ability(id)` assigns an
  ability deterministically by hashing the id against `ABILITY_BY_TYPE[primary]`,
  so a species always has the same ability.
- **`Moves.buildFor(dexId, level, rng)`** — builds a 4-move set: one STAB move
  per type plus filler, capped by a level-based power ceiling (60/75/95/115/∞)
  so a level-5 Pokémon cannot open with Overheat.
- **`createPokemon(dexId, level, opts)`** — the only way to make a Pokémon.
  Rolls IVs, shininess, ability, moves, and calls `recalcStats`. `opts` takes
  `rng`, `shiny`, `shinyRate`, `moves`, `ivs`, `starter`, `heldMegaStone`.
- **`statAt` / `recalcStats` / `expToNext`** — mainline stat formula (no EVs, no
  natures); `expToNext(level) = 12 + level² × 1.6`.
- **`Sprites.front/back/icon`** return an *ordered candidate list* of PokéAPI
  URLs; `Sprites.img()` emits an `<img>` that walks the list via
  `onerror="Sprites.nextFallback(this)"`. That is why sprite style changes never
  produce a broken image.
- **`Profile`** — the permanent account (`pokelike_v9_profile`). `load()`
  backfills defaults over whatever was stored, which is what makes adding a
  field safe. `bump(stat)`, `atLeast(stat, v)`, `seen()`, `caught()`.
- **`Run`** — the current run (`pokelike_v9_run`), plus `encode()`/`decode()`
  for the base64 save code, which bundles profile **and** run.
- **`encounterPool(regionKey, theme, opts)`** — derives a species pool from the
  region's dex range filtered by `THEME_TYPES[theme]`, widening to the whole
  regional dex and then nationally if the themed pool is too small. Cached.
  `opts.rare` flips it to legendaries/mythicals only.
- **`rollEncounter(pool, level)`** — six samples, keeps the one whose BST is
  closest to `220 + level × 5.5` plus noise. This is the difficulty curve for
  wild encounters.
- **`typedRoster(type, region, count)`** — gym/Elite Four teams: highest-BST
  species of that type in the region, shuffled with a stable seed, ace last.
- **`championRoster(type, region, count)`** — not monotype; the strongest team
  the region offers, anchored by two of the champion's signature type, ace last.

## 4. js/map.js

Two independent jobs: build the node graph, and paint the background.

**Graph.** `MapGen.nodes(stage, run)` seeds `mulberry(hashStr(stage.id + seedSalt))`
and lays out 5–6 rows (minus 2 for the Speedrun challenge) of 1–2 nodes each,
bottom to top, from a `start` node to a `cap` node. `cap` is the gym for a gym
stage (with a hidden `exit` behind it) or the exit otherwise. `MapGen.kindBag`
decides what kinds go in the bag, weighted by theme. League stages bypass all of
this via `MapGen.leagueNodes()`: heal → mart → four elites → champion, in a line.

Node coordinates are authored in canvas space (544×896) and placed by the UI as
percentages, so the map scales with the viewport.

**Painting.** `MapGen.paint(canvas, stage, nodes)` prefers a real map picture
(`MapImages.get`) and falls back to the tile engine. `paintImage` covers the
panel and crops, capped at `MAX_UPSCALE = 2.2` so a wide-and-short town map is
not blown up into a single house; when the cap bites, the tile map is painted
behind it. The crop window is stable per area (`mulberry(hashStr('crop' + id))`).

`paintTiles` → `buildGrid` (carves the trail along the node graph) →
`paintGround` (tile painters) → `paintProps` (borders, scatter, buildings).
Themes are configured in `THEME_CFG` and coloured by `PALETTES`; see
`references/pixel-art.md` for how to work on any of that.

**`SpriteGen`** caches generated node-marker sprites as data URLs:
`npc(cls, t)`, `sign(key, label, body, post)`, `center()`, `mart()`,
`grassPatch()`, `exitGate()`, `stairs()`.

## 5. js/battle.js

`Battle.state` holds one battle; `Poke.Run.state.team` is the player side.

**Damage** (`computeDamage`) is the mainline formula:

```
base = ⌊⌊⌊(2·level/5 + 2) · power · A / D⌋ / 50⌋ + 2
```

then multiplied in order by: type effectiveness (inverted for the Inverse
challenge), STAB (1.5×, or 2× with Adaptability), pinch abilities at ≤⅓ HP,
weather, player-side traits and `lifeOrb`, enemy-side `eviolite`/`assaultVest`
/Nuzlocke's flat 1.1×, `thickFat`/`multiscale`, critical (1/16, doubled by
`scopeLens`), and the 0.85–1.00 spread. Immunities (`levitate`, absorb
abilities, 0× matchups) return early.

**Turn order** (`resolveTurn`): priority first (Quick Claw adds +6), then
effective Speed, coin-flip on a tie. Then each side acts in order, guarding
against acting with a Pokémon that fainted mid-turn.

**Enemy AI** (`chooseEnemyMove`) scores every move with PP as
`power × effectiveness × STAB × accuracy/100 + noise` and takes the best — it
actively targets your weaknesses. It refills PP if everything is exhausted.

**`Battle.act(fn)`** wraps every player action so the `busy` flag is always
released even if the turn throws. Any new player action must go through it or a
thrown error freezes the battle permanently.

Other entry points: `useItem`, `throwBall` (gen-3 four-shake capture, shared
with `Game.attemptCatch` via `catchChance`), `megaEvolve`, `flee`, `grantExp` /
`addExp` / `checkEvolution` / `evolve`, `endOfTurn` (status chip, weather chip,
Speed Boost, Leftovers, Berry Pouch), and `finish(win, opts)` which reverts
megas, pays out, records stats and hands back to `UI.closeBattle` →
`Game.afterBattle`.

## 6. js/game.js

The run flow. `Game.draft` holds the pre-run selections; `Poke.Run.state` is the
run once it starts.

- **`beginRun(starterId)`** builds the whole run state — read it to learn every
  field that exists.
- **`stage()`** resolves the current area (`REGIONS[region].stages[stageIndex]`,
  or a re-themed cycling area for the tower). **`stageLevel()`** is the
  difficulty curve: `4 + progress% × 62 + badges × 1.5`, or `18 + floor × 2` in
  the tower, +5 for Speedrun.
- **`handleNode(node)`** is the router — one `case` per node kind. Every branch
  must eventually call `Game.clearNode()`, which marks the node cleared and
  **closes its siblings**, opening only that node's own successors. Miss it and
  the player is stranded with no available nodes.
- **`afterBattle(win, opts)`** handles capture, defeat (only a full wipe ends the
  run), and win rewards. Reward screens are sequenced through `runSteps` so a
  badge screen is never clobbered by the trait screen behind it.
- **`gameOver()` / `winRun()`** end the run, write the Hall of Fame entry and
  clear the save.

## 7. js/ui.js

Pure rendering. Every method reads state and writes markup; none of it owns
state. `UI.show(id)` switches screens, `UI.overlay(html, opts)` opens the modal
(`locked: true` blocks the close button for screens that must be answered),
`UI.toast`, `UI.message`. `UI.pace(ms)` scales battle delays by the
`fastBattle` setting — route timing through it.

`renderAll()` fans out to `renderTopbar/renderTeam/renderBag/renderPassives/
renderTraits/renderBadges/renderNodes`. `renderBattle()` redraws the whole
battle screen from `Battle.state`. Modal screens: `showPokedex`, `showDexEntry`,
`showAchievements`, `showHallOfFame`, `showSettings`, `showSaveCode`,
`showImport`, `showMegaBracelet`, `showStageInfo`, `showMart`, `showPokemonDetail`.

Handlers are attached as `el.onclick = …` right after the markup is written,
because the markup is replaced wholesale on every render — there is no
delegation. Add a button, wire it in the same function that emitted it.

## 8. State shapes

### Profile — `localStorage['pokelike_v9_profile']`

```
version, playerName, gender
dex:          { seen: {id:1}, caught: {id:n}, shiny: {id:1} }
achievements: { achievementId: unlockedAtMs }
stats:        { wins, losses, captures, badges, champion, towerBest, megas,
                evolutions, shinySeen, shinyCaught, legendaries, richest, … }
hof:          { entries: [ {player, region, mode, date, team[]} ], regions: {} }
tower:        { best, unlocked: {region: floor} }
challenges:   { done: [], daily: seed }
settings:     { volume, sfx, cries, spriteStyle, animations, fastBattle,
                confirmRisky, showTypes }
```

`DEFAULT_SETTINGS` and `DEFAULT_STATS` are merged over the loaded object, so new
keys appear automatically on old saves. Removing or renaming a key is the
breaking change.

### Run — `localStorage['pokelike_v9_run']`

```
version, mode ('story'|'tower'), rawMode, submode ('classic'|'nuzlocke'),
challenge, monotype, region, player, gender, seedSalt,
stageIndex, towerFloor, towerRegion,
currentNode, cleared[], available[],
team[], box[], bag{}, passives[], traits{type:tier}, badges[],
money, eliteIndex, repel, pendingEvolutions[], startedAt, savedAt
```

`Game.continueRun()` is where legacy runs get patched up (it backfills `traits`,
`passives` and missing `stats`). Any run-state field that changes shape needs a
migration there.

### A Pokémon

```
dex, name, nick, level, exp, ivs[6], shiny, types[], ability,
moves[{i, pp, maxPp}], status, statusTurns, stats{hp,atk,def,spa,spd,spe},
hp, heldMegaStone, mega|null, starter, origin, uid, dead?
```

`stats` is derived — always change `level`/`ivs`/`mega` and call
`recalcStats(p)`, never write `stats` directly. `displayName(p)`,
`displayTypes(p)` and `spriteDex(p)` resolve the mega form when one is active.
